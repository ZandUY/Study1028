## 二、与之前的工作不同之处

| 类型 | 生成目标 | 主要验证对象 |
| --- | --- | --- |
| 既有 LLM 证明生成 | 生成 Lean、Coq、Dafny 等语言中的证明或完整程序 | 交互式证明器或对应验证器 |
| 本文 | 为给定的 Rust 实现和 Verus 规格补充证明标注 | Verus 与底层 SMT 求解器 |

### Agent 数量与协作方式

本文采用的是**多个专用 Agent 按阶段顺序协作**，而不是让一个通用 Agent 反复阅读完整错误信息。AutoVerus 将证明构造划分为三个阶段：

```
Rust 实现 + Verus 规格
阶段 1：Generation，1 个初步生成 Agent，一次生成 5 组循环不变量候选
阶段 2：Refinement，常量传播、数组长度、量词和条件不变量 Agent
阶段 3：Debugging，按 Verus 错误类型选择约 10 个专用修复 Agent
```

## 三、一个简单例子

论文使用 `count_digits` 说明自动生成证明标注的任务。函数遍历字节数组，统计字符 `'0'` 到 `'9'` 的数量。其规格函数递归定义正确结果：

```rust
spec fn cnt_dig(seq: Seq<u8>) -> int
    decreases seq.len(),
{
    if seq.len() == 0 {
        0
    } else {
        cnt_dig(seq.drop_last())
        + if is_digit(seq.last()) { 1 } else { 0 }
    }
}
```

真实 Rust 函数已经写好，后置条件要求返回值与规格函数一致：

```rust
fn count_digits(text: &Vec<u8>) -> (ret: usize)
    ensures ret == cnt_dig(text@),
{
    let mut count = 0;
    let mut i = 0;

    while i < text.len() {
        if text[i] >= 48 && text[i] <= 57 {
            count += 1;
        }
        i += 1;
    }
    count
}
```

仅有实现和规格时，Verus 无法自动知道循环执行到位置 `i` 时，`count` 表示什么。AutoVerus 需要补充下面的循环不变量：

```rust
while i < text.len()
    invariant
        i <= text.len(),
        count <= i,
        count == cnt_dig(text@.subrange(0, i as int)),
{
    // 原循环体不变
}
```

其中，第一条保证索引合法，第二条帮助证明 `count += 1` 不溢出，第三条说明 `count` 等于前 `i` 个字符中的数字数量。AutoVerus 还会生成关于 `Seq::subrange` 和 `drop_last` 的静态 `assert`，帮助 SMT 求解器连接循环性质与函数后置条件。这些证明标注最终会被擦除，不产生运行时检查。

## 四、如何评估：由 Verus 自动判断证明是否正确

```
评估器检查
   Safety：是否保持原 Rust 实现不变
   Specification：是否保持原前置、后置条件不变
   Validity：程序是否能够被 Verus 编译
   Correctness：Verus 是否完整验证所有目标
```
