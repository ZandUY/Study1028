# 基于大模型的软件建模

| 方向           | 输入                                           | 方法                                                         | 输出                                 |
| -------------- | ---------------------------------------------- | ------------------------------------------------------------ | ------------------------------------ |
| 从描述得到模型 | 需求文本、用户故事、目标建模语言的规则或示例   | 说明建模任务并提供少量示例；让大模型输出 PlantUML 等文本     | 新模型                               |
| 改进已有模型   | 现有模型、需求、错误信息或建模规则             | 指出缺失或冲突的位置，让大模型提出局部修改                   | 新增的模型元素、修复后的模型         |
| 模型验证       | 待检查的模型                                   | 大模型对照需求逐项检查，或辅助产生检查条件，再结合语法检查、约束求解等工具核实 | 问题报告                             |
| 模型转换       | 源模型、目标建模语言的规则、转换示例           | 给出源与目标的对应示例，大模型逐项映射元素                   | 目标模型                             |
| 代码生成       | 类图、状态机等模型，加上目标编程语言和项目约束 | 按模型元素生成代码，再编译、运行测试，并根据错误反馈修改     | 类、接口、状态处理逻辑或其他代码     |
| 模型迁移       | 旧模型、旧版与新版的建模规则，以及版本变化说明 | 找出旧模型中不再合法的元素，生成迁移或修复方案，再检查新版模型 | 符合新版规则的新模型                 |
| 设计建模语言   | 领域术语、业务规则、示例模型，以及语言设计要求 | 让大模型从例子中归纳语言结构，生成语法草案，再用解析和实例测试反复修改 | 语言语法、记法、约束，或相关工具配置 |
