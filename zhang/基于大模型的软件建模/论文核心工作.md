| 类型                     | 生成结果如何检查                                             |
| ------------------------ | ------------------------------------------------------------ |

## 三、一个简单例子

自然语言需求：

```text
定义一个车轮 Wheel。车轮具有轮毂直径 hubDiameter，
轮胎 tire 具有宽度 width，并计算车轮外径 outerDiameter。
```

大模型第一次生成 SysMLv2：

```sysml
package Demo {
  part def Wheel {
    attribute hubDiameter : LengthValue;
    part tire {
      attribute width : LengthValue;
    }
    attribute outerDiameter : LengthValue =
      hubDiameter + 2 * tire.height;
  }
}
```

这段代码的语法结构合法，因此可以通过 ANTLR 解析；但 `tire` 中没有定义 `height`，生产级检查器 SysIDE 会报错：

```text
error (reference-error): No Feature named 'height' found.
```

本文不是直接丢弃该结果，而是把原始需求、当前模型和检查器报错一起反馈给大模型：

```
自然语言需求
      ↓
大模型生成候选 SysMLv2
      ↓
SysIDE 生产一致性检查
      ├── 0 个错误 → 输出最终模型
      └── 存在错误 → 构造修复提示 → 大模型重新生成
                                      ↑       │
                                      └───────┘
```

循环一直持续到 SysIDE 报告 0 个错误。该方法相当于利用“编译器报错”指导大模型修改代码。

## 四、如何评估：比较单次生成与迭代修复

```
SysMBench：151 条自然语言提示
├── OpenAI Codex 5.2
├── Anthropic Sonnet 4.6
├── DeepSeek Reasoner
└── Mistral Large
        ↓
共 151 × 4 = 604 个“提示-模型”案例
        │
        ├── Single-shot
        │   └── 第一次生成的模型是否通过 SysIDE
        │
        └── Pipeline
            └── 根据 SysIDE 报错迭代修复后是否通过
```

此外，论文还比较同一个初始模型能否通过 ANTLR 与 SysIDE，从而量化“语法正确”和“生产工具可用”之间的差距。

## 五、实验结果

| 指标                         | 结果                |
| ---------------------------- | ------------------- |
| 单次生成的生产一致性通过率   | 309/604（51.16%）   |
| 迭代修复后的通过率           | 604/604（100.00%）  |
| 1 轮修复后的累计通过率       | 84.44%              |
| 2 轮修复后的累计通过率       | 94.37%              |
| 4 轮修复后的累计通过率       | 99.67%              |
| 最多修复轮数                 | 7 轮                |

在 604 个初始模型中，369 个通过 ANTLR 语法解析，但其中 60 个仍未通过 SysIDE，占语法正确模型的 16.26%。这说明语法正确是生产可用的必要条件，但不是充分条件。

需要注意，本文的 100% 只表示模型最终能够被 SysIDE 接受，不代表模型一定准确表达了自然语言需求。语义正确性、需求完整性、架构合理性以及跨工具一致性仍需要进一步验证。
